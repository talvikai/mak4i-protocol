## Summary

Defines the required and optional metadata fields for a MAK4I artifact.

> **Profile note (2026-10-12).** MAK4I has two knowledge profiles
> ([MAK-0009 §2](MAK-0009.md#2-knowledge-profiles)). This schema is packaging metadata
> for the **Distributable Artifact** profile: organization-scoped knowledge
> shared with that organization's projects (a public registry is not
> implied). Project records ([MAK-0005 Part A](MAK-0005.md#part-a--governed-project-records-normative))
> are a different shape. Here `version` is a **package version**, never a
> project-record revision. The field mapping onto the Distributable
> Artifact profile is in [MAK-0009 §2.2](MAK-0009.md#2-knowledge-profiles).

---

## Motivation

For artifacts to be portable across registries and platforms,
a common metadata schema is required.

This schema defines what an artifact *is* — the minimum fields needed for
discovery, versioning, and reuse decisions. It does not attempt to define
every possible metadata field a format could carry (provenance sourcing,
trust tiers, and similar descriptive metadata are the domain of formats
like [OKF](https://github.com/google/okf), and MAK4I is designed to
consume that metadata rather than duplicate it — see
[ARCHITECTURE.md](../ARCHITECTURE.md)). What this schema and the
standards that build on it are responsible for is enabling the
*behavior* MAK4I enforces — discovery, reuse, and adaptation — not
serving as a general-purpose knowledge-description format in its own
right.

Without a standard schema:
- Artifacts cannot be shared between registries
- Injection clients cannot parse artifacts consistently
- Version resolution cannot work across implementations
- The protocol cannot be certified or tested

MAK-0001 defines the minimum required schema that every
MAK4I-conformant artifact must implement.

## Specification

### Required Fields

Every MAK4I artifact MUST include these fields:

```json
{
  "id": "string",
  "version": "string (semver)",
  "type": "string (procedural | semantic | episodic)",
  "name": "string",
  "description": "string"
}
```

| Field | Type | Description |
|-------|------|-------------|
| `id` | string | Unique identifier: `name` or `org/name`. Each segment is lowercase letters and digits joined by single hyphens (`[a-z0-9]+(-[a-z0-9]+)*`). |
| `version` | string | Package version, semantic: `MAJOR.MINOR.PATCH` (never a project-record revision). |
| `type` | enum | Memory type: `procedural`, `semantic`, or `episodic` |
| `name` | string | Human-readable name |
| `description` | string | What this artifact contains and when to use it |

### Optional Fields

MAK4I artifacts MAY include these fields:

```json
{
  "layer": "string",
  "tags": ["string"],
  "ai_platforms": ["string"],
  "injection_hint": "string",
  "token_estimate": "integer",
  "content": "string | object",
  "author": "string",
  "license": "string",
  "created_at": "ISO 8601 date",
  "updated_at": "ISO 8601 date",
  "dependencies": ["artifact-id"],
  "deprecated": "boolean",
  "deprecated_by": "artifact-id"
}
```

| Field | Type | Description |
|-------|------|-------------|
| `layer` | string | Sub-classification within the memory type |
| `tags` | string[] | Searchable tags for registry discovery |
| `ai_platforms` | string[] | Compatible AI platforms (claude, chatgpt, gemini, any) |
| `injection_hint` | string | How to inject: inline, prepend, append, system |
| `token_estimate` | integer | Estimated size of `content` in tokens. (Savings figures such as "tokens saved per session" are reporting metrics, not artifact metadata.) |
| `content` | string \| object | The artifact's knowledge itself. Optional: an artifact may be metadata-only and point elsewhere. |
| `author` | string | Author email or identifier |
| `license` | string | SPDX license identifier |
| `created_at` | string | ISO 8601 creation date |
| `updated_at` | string | ISO 8601 last updated date |
| `dependencies` | string[] | Other artifact IDs this artifact depends on |
| `deprecated` | boolean | Whether this artifact is deprecated |
| `deprecated_by` | string | Artifact ID that replaces this one |

## Examples

### Minimal conformant artifact

```json
{
  "id": "fastapi-scaffold",
  "version": "1.0.0",
  "type": "procedural",
  "name": "FastAPI Scaffold",
  "description": "Standard FastAPI project structure and bootstrap code"
}
```

### Full artifact

```json
{
  "id": "example-org/booking-app-stack-context",
  "version": "1.0.0",
  "type": "semantic",
  "layer": "context",
  "name": "Booking App Stack Context",
  "description": "Stack overview for an example booking application, so sessions don't re-explain the architecture: managed auth, React front end, Node.js API on a container platform, PostgreSQL, Redis, SMS and email providers.",
  "content": "Front end: React. API: Node.js on a container platform. Data: PostgreSQL + Redis. Auth: managed identity provider. Messaging: SMS and email providers.",
  "token_estimate": 60,
  "ai_platforms": ["claude", "chatgpt", "any"],
  "injection_hint": "prepend",
  "tags": ["example", "stack", "context"],
  "author": "maintainers@talvik.ai",
  "license": "MIT",
  "created_at": "2026-06-23",
  "updated_at": "2026-06-25"
}
```

## Validation Rules

An artifact is valid under MAK-0001 when it validates against
[`artifact.schema.json`](../schemas/artifact.schema.json), which encodes these rules:

1. All REQUIRED fields are present and non-empty
2. `id` is `name` or `org/name`, each segment lowercase letters and digits joined by single hyphens
3. `version` follows semantic versioning (X.Y.Z)
4. `type` is one of: `procedural`, `semantic`, `episodic`
5. `token_estimate` if present is a positive integer
6. `created_at` and `updated_at` if present are valid ISO 8601 dates
7. Optional fields, if present, have the types listed above; other fields
   follow the extensibility rules in [SPEC.md](../SPEC.md#extensibility) (`x_<vendor>_` prefix)

## Conformance

A document conforms to MAK-0001 (the **Artifact** profile,
[CONFORMANCE.md](../CONFORMANCE.md#conformance-profiles), criteria A1–A4) when it passes the validation
rules above. There is no certification badge yet (approved future scope).

## Open Questions

Decided on 2026-10-12:

1. *Should `content` be a required field?* **No.** `content` is an
   optional field defined here.
2. *Should `id` support namespacing (`org/name`)?* **Yes**, now, with the
   strict pattern above.
3. *What does `token_estimate` measure?* **The estimated size of
   `content` in tokens.** Splitting guidance is not normative.

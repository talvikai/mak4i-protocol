# MAK-0001 — Artifact Metadata Schema

**Status:** Draft  
**Version:** 0.1  
**Created:** August 2026  
**Author:** Aswin Kumar Balakrishnan, Talvik Inc.  
**Type:** Core Standard  

---

## Summary

Defines the required and optional metadata fields for a MAK4I artifact.

---

## Motivation

For artifacts to be portable across registries and platforms,
a common metadata schema is required.

This schema defines what an artifact *is* — the minimum fields needed for
discovery, versioning, and reuse decisions. It does not attempt to define
every possible metadata field a format could carry (provenance sourcing,
trust tiers, and similar descriptive metadata are the domain of formats
like [OKF](https://github.com/google/okf), and MAK4I is designed to
consume that metadata rather than duplicate it — see
[ARCHITECTURE.md](../ARCHITECTURE.md)). What this schema and the
standards that build on it are responsible for is enabling the
*behavior* MAK4I enforces — discovery, reuse, and adaptation — not
serving as a general-purpose knowledge-description format in its own
right.

Without a standard schema:
- Artifacts cannot be shared between registries
- Injection clients cannot parse artifacts consistently
- Version resolution cannot work across implementations
- The protocol cannot be certified or tested

MAK-0001 defines the minimum required schema that every
MAK4I-conformant artifact must implement.

## Specification

### Required Fields

Every MAK4I artifact MUST include these fields:

```json
{
  "id": "string",
  "version": "string (semver)",
  "type": "string (procedural | semantic | episodic)",
  "name": "string",
  "description": "string"
}
```

| Field | Type | Description |
|-------|------|-------------|
| `id` | string | Unique identifier. Format: `org/name` or `name`. Lowercase, hyphens only. |
| `version` | string | Semantic version. Format: `MAJOR.MINOR.PATCH` |
| `type` | enum | Memory type: `procedural`, `semantic`, or `episodic` |
| `name` | string | Human-readable name |
| `description` | string | What this artifact contains and when to use it |

### Optional Fields

MAK4I artifacts MAY include these fields:

```json
{
  "layer": "string",
  "tags": ["string"],
  "ai_platforms": ["string"],
  "injection_hint": "string",
  "token_estimate": "integer",
  "author": "string",
  "license": "string",
  "created_at": "ISO 8601 date",
  "updated_at": "ISO 8601 date",
  "dependencies": ["artifact-id"],
  "deprecated": "boolean",
  "deprecated_by": "artifact-id"
}
```

| Field | Type | Description |
|-------|------|-------------|
| `layer` | string | Sub-classification within the memory type |
| `tags` | string[] | Searchable tags for registry discovery |
| `ai_platforms` | string[] | Compatible AI platforms (claude, chatgpt, gemini, any) |
| `injection_hint` | string | How to inject: inline, prepend, append, system |
| `token_estimate` | integer | Estimated tokens saved per injection |
| `author` | string | Author email or identifier |
| `license` | string | SPDX license identifier |
| `created_at` | string | ISO 8601 creation date |
| `updated_at` | string | ISO 8601 last updated date |
| `dependencies` | string[] | Other artifact IDs this artifact depends on |
| `deprecated` | boolean | Whether this artifact is deprecated |
| `deprecated_by` | string | Artifact ID that replaces this one |

## Examples

### Minimal conformant artifact

```json
{
  "id": "fastapi-scaffold",
  "version": "1.0.0",
  "type": "procedural",
  "name": "FastAPI Scaffold",
  "description": "Standard FastAPI project structure and bootstrap code"
}
```

### Full artifact (WD Technology example)

```json
{
  "id": "schedovia-stack-context",
  "version": "1.0.0",
  "type": "episodic",
  "layer": "context",
  "name": "Schedovia Stack Context",
  "description": "Full stack context for Schedovia — eliminates re-explaining architecture each session. Covers Firebase Auth, React, Node.js, GCP Cloud Run, Cloud SQL, Redis, Twilio, Resend, Square.",
  "token_estimate": 1500,
  "ai_platforms": ["claude", "chatgpt", "any"],
  "injection_hint": "prepend",
  "tags": ["schedovia", "stack", "context", "wdtech"],
  "author": "aswin@wdtechnologysolutions.com",
  "license": "MIT",
  "created_at": "2026-06-23",
  "updated_at": "2026-06-25"
}
```

## Validation Rules

An artifact is valid under MAK-0001 when:

1. All REQUIRED fields are present and non-empty
2. `id` contains only lowercase letters, numbers, hyphens, and forward slashes
3. `version` follows semantic versioning (X.Y.Z)
4. `type` is one of: `procedural`, `semantic`, `episodic`
5. `token_estimate` if present is a positive integer
6. `created_at` and `updated_at` if present are valid ISO 8601 dates

---

## Conformance

An artifact is **MAK4I Certified** under MAK-0001 when it:

- Passes all validation rules above
- Can be parsed by the MAK4I reference implementation
- Successfully injects into at least one supported AI platform
